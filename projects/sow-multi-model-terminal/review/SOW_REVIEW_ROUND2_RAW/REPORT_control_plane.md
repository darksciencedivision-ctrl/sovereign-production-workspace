### B. New findings
CP-N1 | MEDIUM | [OBSERVED bind / INFERRED interception] | IPC gateway uses SO_REUSEADDR on Windows → local co-bind of the loopback control channel
gateway.py:256-257 `class Server(ThreadingTCPServer): allow_reuse_address = True`. On Windows SO_REUSEADDR lets ANY local socket that also sets SO_REUSEADDR bind the same 127.0.0.1:port while the gateway is listening (SO_EXCLUSIVEADDRUSE is what prevents it). Executed: second bind on the live gateway port SUCCEEDED (plain bind → WinError 10048). Which listener receives a given connection is documented as non-deterministic; in my one trial the original won. A local process can thereby race/steal or wedge the shell↔control-plane channel — the channel whose loss the ticket says makes the shell "kill every session on loss" (emit_worker_launch.py:774-776); an interceptor also sees the bearer `auth.node_credential` (cannot forge HMAC without the key). Fix: `allow_reuse_address = False` on win32 (or setsockopt SO_EXCLUSIVEADDRUSE) here and in any sibling servers.

Fix shape: wire job-object assignment into the pid→attest step (`attest_spawned`) or the shell spawn.

CP-N3 | MEDIUM | [OBSERVED] | Durable lease release paths do not survive a Windows sharing-violation; refusal path can crash and strand a counted terminal

Fix: bounded retry on PermissionError inside `_write`, and catch OSError at both release sites (report `lease_released:false`).
